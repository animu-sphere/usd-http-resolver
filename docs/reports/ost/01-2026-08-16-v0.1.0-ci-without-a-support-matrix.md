# OST v0.1.0 CI without a support matrix

- Date: 2026-08-16
- Release target: `v0.1.0`
- OST version exercised: `ost 0.22.2`
- Runtime: none — this is the lane whose claim is that it needs none
- Platforms exercised locally: Windows x86_64 (MSVC 19.34), Linux x86_64
  (WSL2 Ubuntu 26.04, GCC 15.2.0)
- Source revision: `153d56d` (`main`, merge of PR #2)
- Scope: the `v0.1.0` CI cells — the OpenUSD-free core lane and the sanitizer
  lanes — and why they are not `ost ci generate github` output

The roadmap's next item was "write `openstrata.ci.yaml` with the core cell, the
sanitizer cells, and the Windows, Linux, and macOS arm64 rows, and generate the
workflows from it". That file is not what landed. `ost` 0.22.2 has no cell shape
this repository can name at `v0.1.0`, and the reason is structural rather than a
missing pin. This report records what was tried, what the tool said, and what
landed instead.

It also answers the open item left by `usd-pointcloud-plugins`
[report 04](https://github.com/animu-sphere/usd-pointcloud-plugins/blob/main/docs/reports/ost/04-2026-08-16-usd-http-resolver-preimplementation.md)
§3 — "the resolver repository should add `openstrata.ci.yaml` when it introduces
CI coverage". CI coverage was introduced; the matrix still cannot hold it.

## 2. Why no cell shape fits

`ost` 0.22.2 offers three, and each is refused for its own reason.

**A `bundle:` cell** names a directory containing an `openstrata.plugin.yaml`.
`v0.1.0` ships `libs/usd-asset-io`, `libs/usd-asset-local`, and `tests/boundary`
and no bundle at all; `plugins/http-resolver` is a `v0.2.0` deliverable. There
is nothing to name.

**A `kind: workspace` cell** exists precisely for workspace members no bundle
requires, which is what these libraries are. Two things stop it:

1. `SupportCell::runtime_artifact` is a required field, and the rendered job
   verifies and materializes that runtime before it builds. The lane's entire
   claim is that the release builds and tests *with no OpenUSD installed*.
   Pulling a ~120 MB USD runtime into it would not merely be wasteful; it would
   remove the property the cell exists to demonstrate.
2. The rendered build step is `ost build --target … --profile …`, with no
   preset, no `--intent`, and no cache-variable hook. Neither
   `USD_HTTP_RESOLVER_BUILD_PLUGIN=OFF` nor
   `USD_HTTP_RESOLVER_SANITIZER=address,undefined` is reachable from the
   matrix, so the sanitizer cells the roadmap asked
   for cannot be written even with the runtime cost accepted. `source_checks`,
   which could carry them as extra steps, render only in bundle jobs.

**A `verify: graph` cell** was the one shape that looked viable: it is the cheap
rung, its job stops after the checkout, and it never fetches a runtime. It is
refused too, because its gate is a plugin verb:

```text
$ ost plugin test --workspace --graph-only --json
{
  "error": {
    "category": "precondition",
    "code": "PRECONDITION_FAILED",
    "hint": "run from the workspace root, or pass a bundle path instead of --workspace",
    "message": "no plugin bundles found in the workspace member set"
  },
  "ok": false,
  "schema": 1
}
```

A matrix declaring no cells is refused as well, so "an `openstrata.ci.yaml` that
documents the contract and declares nothing yet" is not available either:

```text
$ ost ci validate --matrix empty.ci.yaml
error[MANIFEST_INVALID]: manifest is invalid: the support matrix declares no cells
```

The common root: `ost ci` models CI as *a plugin bundle verified against a
pinned runtime*. A workspace whose current deliverable is a runtime-independent
library plus its test suite has no representation in it, and this project spends
one whole release in exactly that state on purpose — the read contract and the
boundary suite exist before any transport, so that the transport is written
against a passing suite.

## 3. What landed instead

`.github/workflows/core-ci.yml`, hand-authored, two jobs:

| Job | Runners | What it runs |
| --- | --- | --- |
| `core` | `ubuntu-24.04`, `macos-15`, `windows-2022` | `cmake --preset core` (`core-msvc` on Windows), build, `ctest` |
| `sanitizers` | `ubuntu-24.04` | `core-asan` and `core-tsan`, as separate matrix rows |

The `core` job does not merely build. It asserts the OpenUSD-free property from
the configure log, because a green build on a runner that happens to carry no
OpenUSD is not evidence of anything: it would stay green the day a `libs/`
module acquires a USD dependency and the runner starts carrying one. The
assertion is that the root returned before `find_package(pxr)` and said so.

Two lanes remain out of the generated world when `openstrata.ci.yaml` lands in
`v0.2.0`, and they should: they need no runtime, and a runtime-free lane is
worth keeping runtime-free.

## 4. Repository-side fixes found on the way

**The UBSan lane was decorative.** UndefinedBehaviorSanitizer's default is to
print a violation and *continue*, so the process exits 0 and CTest reports a
pass. For a project whose stated reason to run UBSan is that "offset and size
arithmetic is where overflow lives", that is the exact failure it was bought to
prevent. Measured on GCC 15.2.0:

```text
$ g++ -fsanitize=address,undefined -g -o ub_recover ub.cpp && ./ub_recover
ub.cpp:2:36: runtime error: signed integer overflow: 2147483647 + 1 cannot be represented in type 'int'
-2147483648
recover-exit=0

$ g++ -fsanitize=address,undefined -fno-sanitize-recover=all -g -o ub_halt ub.cpp && ./ub_halt
ub.cpp:2:36: runtime error: signed integer overflow: 2147483647 + 1 cannot be represented in type 'int'
halt-exit=1
```

The root `CMakeLists.txt` now passes `-fno-sanitize-recover=all` with the
sanitizer flags. ASan already aborts and TSan already sets a non-zero exit code
when it has reported, so this changes only the lane that needed it. The test
presets carry `UBSAN_OPTIONS=print_stacktrace=1` and `TSAN_OPTIONS=halt_on_error=1`
so a local reproduction runs what CI ran.

**The Ninja presets need a developer prompt on Windows.** `core`, `core-asan`,
and `core-tsan` pin the Ninja generator, which requires `cl.exe` already on
`PATH` — true inside a VS developer prompt, false in a plain shell and on a
stock hosted runner, where the failure is a confusing `fatal error C1083:
cannot open include file 'atomic'` rather than a missing compiler. Added
`core-msvc`: the same cache variables through the Visual Studio generator, which
locates the toolchain itself. It is what the Windows cell runs, so the lane a
contributor reproduces is the lane CI runs.

## 5. Sanitizer evidence

The `v0.1.0` exit criterion that the local backend passes the boundary suite
under ASan, UBSan, and TSan is met as of this report. Run locally on WSL2
Ubuntu 26.04, GCC 15.2.0, CMake 4.2.3, against `153d56d` plus the fixes in §4:

```text
$ cmake --preset core-asan && cmake --build --preset core-asan && ctest --preset core-asan
100% tests passed, 0 tests failed out of 9

$ cmake --preset core-tsan && cmake --build --preset core-tsan && ctest --preset core-tsan
100% tests passed, 0 tests failed out of 9
```

Nine tests: four in `usdAssetIo`, two in `usdAssetLocal`, and the boundary
suite's `fixed`, `property`, and `concurrent` rows against the local backend.
CI makes this repeatable rather than anecdotal, which is the point of the lane;
the local run is what makes the criterion met today rather than met on the first
green PR.

## 6. Upstream asks for OpenStrata

Neither is urgent for this repository — `v0.2.0` brings a bundle, and both lanes
are legitimately hand-authored regardless — but both are general.

1. **A runtime-free workspace cell.** A `kind: workspace` cell whose members are
   plain libraries has no reason to pin, verify, or materialize a runtime, and
   for a project whose contract is "these libraries need no runtime", being made
   to pin one inverts the property under test. `runtime_artifact` being required
   on every cell is the blocker.
2. **A build-configuration hook on workspace cells.** `ost build` already
   accepts `--intent` for project-declared cache variables, and
   `[build.intents.*]` in `openstrata.toml` is exactly the right shape for a
   sanitizer lane. The CI renderer does not pass it. An `intent:` key on a
   workspace cell — or `source_checks` rendering in workspace jobs, which would
   also work — would have made the sanitizer cells expressible.

The `verify: graph` rung would additionally be more useful if the workspace
dependency-graph gate did not require a plugin bundle to exist: the edge it
validates is declared in `openstrata.library.yaml` descriptors, which this
workspace has and which currently go unchecked by any lane.

## 7. When this changes

`openstrata.ci.yaml` lands in `v0.2.0` alongside `plugins/http-resolver`, the
first thing here a cell can name. At that point the repository carries both: a
generated support matrix for the bundle, and these two hand-authored lanes for
the runtime-free core. The release gate in
[docs/releases/README.md](../../releases/README.md) is worded for both.
