## 1. What shipped

`v0.3.0` adds `libs/usd-asset-cache`, a transport- and OpenUSD-independent
`AssetReader` decorator. It expands requested ranges to blocks, keeps the final
block at its actual length, coalesces adjacent and near-adjacent misses, and
stores them under an LRU process-wide byte budget. A streaming-sized read
bypasses the cache rather than evicting useful small reads.

The cache identity is `resolvedIdentifier + validator + blockSize + blockIndex`.
The validator remains opaque: it is never parsed as an ETag or compared for
recency. Equal identifiers therefore never imply equal cache contents across
revisions. A shared in-flight registry gives misses for the same identity
single-flight behavior across both threads and independent readers.

The HTTP resolver now decorates every reader it opens. It exposes the four
cache settings in [CONFIGURATION.md](../reference/CONFIGURATION.md), reads them
once during construction, and reports rounding or refusal through the existing
configuration diagnostics. `ReaderMetrics` now absorbs transport metrics so a
decorated stack reports one coherent counter set.

The release also adds:

- the cache metrics defined by [METRICS.md](../architecture/METRICS.md): hits,
  misses, partial hits, saved requests, `bytesOverFetched`, evictions, and
  resident high-water mark;
- a `cache over local` row in the shared boundary suite, which runs the same
  contract cases as the uncached local reader;
- `tests/cache-tuning`, a socket-backed sweep of block sizes and coalescing
  gaps whose findings set the measured policy constants in
  [BLOCK_POLICY.md](../reference/BLOCK_POLICY.md); and
- cached and uncached rows in the I/O-baseline harness, with fixture-server
  request logs as an independent witness for bytes transferred.

The cache contract is [CACHE.md](../architecture/CACHE.md). The module's
dependency boundary and non-goals are recorded in
[`libs/usd-asset-cache/README.md`](../../libs/usd-asset-cache/README.md).

## 2. What explicitly did not ship

No asynchronous read API, prefetcher, persistent cache, shared cache between
processes, or cache-specific transport behavior ships in this release. The
cache does not own HTTP request framing, validator parsing, retry policy, or
OpenUSD integration; those remain below or above the decorator as appropriate.

No binary package ships. This remains a source-tag release; packaged artifacts
are planned for `v0.6.0`.

## 3. Capability delta against `v0.2.0`

- **Cache:** block-aligned reads, true-length final blocks, bounded
  coalescing, process-wide LRU eviction, streaming bypass, and validator-keyed
  identity.
- **Concurrency:** single-flight misses shared across threads and readers for
  one cache identity.
- **Resolver:** cache configuration and a cached `ArResolver` reader stack.
- **Observability:** populated cache counters and one metrics registry for a
  decorated reader stack.
- **Verification:** cached-local boundary coverage, cache tuning measurements,
  and a baseline that reports every scenario with and without the cache.

Revision binding from `v0.2.0` remains unchanged: a reader that observes a
changed validator fails subsequent reads, while a cache hit returns bytes for
the revision to which that reader is already bound.

## 4. Recorded I/O baseline

Fixture: the 128 MiB synthetic asset from
[BASELINE.md](../reference/BASELINE.md), served by the loopback fixture server
with a strong ETag. Every byte is derived from its offset and every scenario
checks the bytes it receives. Counts below are asserted against both reader
metrics and the fixture server's request log.

| Scenario | uncached requests | cached requests | uncached bytes | cached bytes | Result |
| --- | ---: | ---: | ---: | ---: | --- |
| header and index read | 18 | 3 | 69632 | 131072 | Coalescing removes 15 requests; the extra bytes are reported as over-fetch |
| bounded spatial query | 19 | 18 | 331776 | 1507328 | `selectivity` changes from 0.0025 to 0.0112 by design |
| full sequential read | 33 | 33 | 134217728 | 134217728 | Identical; the streaming path bypasses the cache |
| parallel readers | 152 | 25 | 2654208 | 1507328 | Single-flight shares the overlapping misses |

The deliberate trade is explicit: fewer requests and correct bytes, at a
measured `bytesOverFetched` cost for non-streaming reads. The full sequential
case is unchanged, which prevents the cache from disguising a whole-asset
download as an optimization. The complete constants, raw rows, and the policy
selection are recorded in [BASELINE.md](../reference/BASELINE.md) and
[BLOCK_POLICY.md](../reference/BLOCK_POLICY.md).

Windows x86_64, Linux x86_64, and macOS arm64; C++17; CMake 3.23 or newer;
OpenUSD 26.08 within the declared `>=26.08,<27.0` range; and the OpenStrata
matrix specified in `openstrata.ci.yaml`. The core path remains independent of

## 7. Third-party dependencies and licenses

This release adds no third-party dependency. `usd-asset-cache` links only the
project's `usdAssetIo` target. libcurl remains private to `usd-asset-http`, and
OpenUSD remains a runtime dependency of `plugins/http-resolver`; their licenses
and linkage scopes remain recorded in `NOTICE` and in
[the v0.2.0 record](v0.2.0.md).

## 8. Known limitations

- Cache state is process-local and memory-only; it is not a persistent or
  distributed cache.
- A cache hit cannot observe an origin's changed validator. It correctly
  returns data for the reader's already bound revision; a subsequent miss that
  observes a changed validator reports `AssetChanged`.
- Coalescing intentionally increases transferred bytes. The policy is bounded
  and measured, but an application that values exact-byte reads over fewer
  requests can disable the cache through its configuration.
- The cache does not add a `HEAD`-unavailable fallback, relax range-unsupported
  handling, or change the known limitations recorded for the HTTP backend in
  [`v0.2.0`](v0.2.0.md).

## 9. Migration notes

There is no source-level migration for existing `AssetReader` clients. Resolver
users gain four optional cache environment settings; their names, defaults,
bounds, and configuration diagnostics are the compatibility surface documented
in [CONFIGURATION.md](../reference/CONFIGURATION.md). With defaults, callers
may observe fewer transport requests and larger individual range reads while
receiving the same bytes and status behavior.
