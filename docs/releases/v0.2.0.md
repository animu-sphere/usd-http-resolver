## 1. What shipped

The release in which bytes cross a network. `v0.1.0` built the contract and the
suite that enforces it; this one adds the transport that suite was built to
admit, and the OpenUSD bundle that makes it reachable from a `UsdStage`.

| Module | What it is |
| --- | --- |
| `libs/usd-asset-http` | The HTTP backend: single ranges, `HEAD` metadata, bounded redirects, three separate deadlines, bounded retry, resume of a short transfer, and framing validated against the *request* rather than against the response. libcurl lives in one translation unit behind the internal transport seam [ADR-0003](../adr/0003-http-client-dependency.md) requires, and appears in no installed header |
| `plugins/http-resolver` | The `ArResolver` bundle, and the first module in this repository that includes an OpenUSD header. Registers `http` and `https` as URI schemes — not as the primary resolver, so installing it never changes how a local asset opens — normalizes and anchors identifiers per RFC 3986, hands out an `ArAsset` over the backend's reader, and projects the typed vocabulary onto the `HTTPxxx` codes |
| `tests/fixture-server` | The hostile-server corpus: 18 behaviors covering all nine conditions in §11.2 of the [design policy](../design/DESIGN_POLICY.md), plus three the ADRs and DIAGNOSTICS.md add. Self-checked over a raw socket by a client that shares no HTTP code with it, and its coverage asserted at runtime against `AllBehaviors()` rather than claimed |
| `tests/corpus` | Every corpus behavior projected onto a `StatusCode`, so that "the backend handles a hostile server" is a table rather than a sentence |
| `tests/baseline` | The recorded I/O baseline: the five scenarios [METRICS.md](../architecture/METRICS.md) §6 requires, against a 128 MiB synthetic asset on loopback, with byte and request counts asserted exactly and ratios reported. Record: [BASELINE.md](../reference/BASELINE.md) |

Both prerequisites §17 of the design policy fixes were done first, in the order
it fixed them — the client decision recorded as an ADR, then the corpus standing
up — and `libs/usd-asset-http` was written against two things that already
passed. Neither prerequisite ships in the release.

Revision binding is the property the release turns on, and it sits here rather
than with the cache because it is a correctness property of range reads
themselves: a reader that issues three requests without a validator can compose
three revisions into one byte sequence with no request failing. A validator is
captured at open and classified; `If-Range` goes on every range request the
capture admits one for; and two independent detectors report `AssetChanged` — a
`200` answering a conditional range, and a response whose validator or complete
length contradicts the capture.

Supporting infrastructure: `openstrata.ci.yaml` and the six generated
`pull_request` cells in `.github/workflows/ost-source-ci.yml`, which could not
exist before a bundle existed to name; `.github/workflows/plugin-windows-ci.yml`,
hand-authored because no generated cell can hand CMake the vcpkg prefix libcurl
needs on Windows; and the `plugin-msvc` preset.

The claim `v0.1.0` made was that adding a transport adds a row, not a suite.
`tests/boundary/backends/boundary_http_main.cpp` is 152 lines and is that claim
cashed: not one line of `tests/boundary` was changed to admit it.

## 2. What explicitly did not ship

No cache, of any kind. The cache counters are defined and stay at zero, and
`amplification` is exactly 1.000000 in every scenario that moves a byte because
there is nothing to over-fetch. No async, no prefetch, no persistence.

No fallback for a server that refuses `HEAD`. §4.1 of the design policy admits
"a minimal metadata request where `HEAD` is unavailable"; a `405` or `501` is
reported as `Unsupported` instead. This is a decision and not an oversight: the
hostile corpus has no row that refuses `HEAD`, so a fallback written now would
ship unexercised, and this repository's rule is to name a gap rather than fill it
speculatively.

No binary package. This is a source tag, and packaging is `v0.6.0`'s scope; see
§5, gate 9, for what was measured anyway.

No identity exposure through `GetAssetInfo`, and no cross-stage reuse rules.
Those are `v0.4.0`, and they depend on validators being trustworthy first, which
is what this release establishes.

## 3. Capability delta against `v0.1.0`

Newly *implemented* in [the capability matrix](../reference/CAPABILITY_MATRIX.md)
at this tag:

- **Transport**: HTTP/HTTPS `GET`, range requests, `HEAD` metadata, redirects,
  three separate timeouts, bounded retry, malformed-framing refusals, resume of
  a short transfer, range-unsupported as a hard error, and a response body
  bounded by the request.
- **Resolution**: `http` / `https` URI scheme registration, URI normalization,
  relative resolution against a remote anchor, `ArAsset` range reads, extension
  detection through a query string, one metadata request per resolution reused
  by the open, and absence distinguished from failure.
- **Identity**: HTTP validator capture and classification, `If-Range` on every
  range request the capture admits, revision binding over both backends, and
  `AssetChanged` detection with two independent detectors.
- **Diagnostics and metrics**: the `HTTPxxx` plugin codes, HTTP-populated
  counters and latency histograms, and recorded baselines.
- **Configuration**: the five transport bounds from the environment
  ([CONFIGURATION.md](../reference/CONFIGURATION.md) §2).
- **Process**: the hostile corpus and its self-test, the corpus projection, the
  generated OpenStrata support matrix, and the hand-authored Windows plugin lane.

Unchanged from `v0.1.0`: `libs/usd-asset-io` and `libs/usd-asset-local` carry no
source change in this release. Their OpenStrata descriptors therefore stay at
`0.1.0` while `usdAssetHttp` enters at `0.2.0`; module versions track modules,
and the release version is the tag.

Still *not implemented*: the `HEAD`-unavailable fallback, and `HTTP102`, which
ADR-0002 defers by making range-unsupported terminal.

## 4. Recorded baseline

The first one this project has. It is reproduced here in full from
[BASELINE.md](../reference/BASELINE.md) at this tag, which is what
[gate 6](README.md) binds a release to.

Fixture: a synthetic asset of 134217728 bytes (128.0 MiB) at
`/baseline/asset.bin` on the loopback fixture server, ephemeral port,
`Behavior::Normal`, strong `ETag`. Every byte is a hash of its own offset, so a
read landing at the wrong offset returns data that is obviously from elsewhere,
and every scenario verifies the bytes it counted. Layout: a 4096-byte header at
offset 0, a 65536-byte index in the tail, body between them. Measured with the
shipped transport defaults, on Windows AMD64, MSVC 19.34.31937.0, Release.

| Scenario | requests | metadata | retries | redirects | bytes requested | bytes transferred | amplification | selectivity | wall ms |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| metadata-only open | 1 | 1 | 0 | 0 | 0 | 0 | — | 0.000000 | 1.4 |
| header and index read | 18 | 1 | 0 | 0 | 69632 | 69632 | 1.000000 | 0.000519 | 1.4 |
| bounded spatial query | 19 | 1 | 0 | 0 | 331776 | 331776 | 1.000000 | 0.002472 | 1.5 |
| full sequential read | 33 | 1 | 0 | 0 | 134217728 | 134217728 | 1.000000 | 1.000000 | 131.0 |
| parallel readers | 152 | 8 | 0 | 0 | 2654208 | 2654208 | 1.000000 | 0.019775 | 3.5 |

**The headline is `selectivity` on the bounded query: 0.0025.** A query that read
a header, an index, and sixteen scattered chunks moved 324 KiB of a 128 MiB
asset, and every byte it moved was a byte the caller asked for.
**`amplification` is exactly 1.000000 wherever a byte moved**, because there is
no cache — which makes it the number that can only get worse, and the reason it
is written down before `v0.3.0` trades it for a smaller request count. The full
sequential read moved the same content bytes as a plain `GET` performed by the
fixture server's own raw client, in a comparable time: 33 requests against 1,
131.0 ms against 120.0 ms, recorded and not gated because the comparator reads
4 KiB at a time and a comparison that flatters is not a gate.

Every cache counter in METRICS.md §2.2 is zero because no cache exists, not
because none hit.

**Regression against the previous release: none possible.** `v0.1.0` recorded no
baseline and was not required to; §4 of [its record](v0.1.0.md) states why. This
table is the first, and every later release is measured against it.

Gate 9 is recorded as *not applicable* rather than *pass*, on the rule in
[README.md](README.md): it binds a release that publishes a binary package, and a
source tag is pinned by the tag. Packaging is `v0.6.0`'s scope. But this is the
first release whose install rules produce a bundle at all, so the measurement was
made rather than deferred: two independent configure-and-build runs of the same
tree into two prefixes, on Windows, MSVC, Release.

Twenty-four of the twenty-eight installed files are byte-identical — every
header, every generated CMake package file, the regenerated `plugInfo.json`, the
manifest, and the fixtures. Four differ: `usdAssetIo.lib`, `usdAssetLocal.lib`,
`usdAssetHttp.lib`, and `libHttpResolver.dll`. They differ in almost nothing.
`libHttpResolver.dll` is the same size and differs in exactly **two bytes**: one
in the COFF `TimeDateStamp` at file offset `0x110`, and one in the debug
directory's copy of the same stamp — 17:45:26 UTC against 17:45:35 UTC, nine
seconds apart. The static libraries differ in 54 bytes beginning at offset 32,
which is the archive member header's timestamp field. Not one byte of code, data,
or relocation differs.

So what stands between this tree and a reproducible package is the embedded build
clock and nothing else, and closing it is a link flag (`/Brepro` on MSVC,
`SOURCE_DATE_EPOCH` elsewhere) rather than a design change. That is recorded here
as an input to `v0.6.0` rather than applied now: changing link flags after the
release lanes are green would invalidate the evidence this record is made of.

## 7. Third-party dependencies and licenses

One, and it is new in this release.

| Dependency | Version | License | How it is linked |
| --- | --- | --- | --- |
| libcurl | The host's; `8.13.0-DEV` on the Windows lane, the runner's package elsewhere | curl (MIT/X11 derivative) | Acquired through `find_package`, linked **privately** by `libs/usd-asset-http` alone, and statically where the triplet provides it. No libcurl source is vendored, nothing is fetched at configure time, and no libcurl type appears in any installed header |
| OpenUSD | 26.08 | Apache-2.0, with the modifications in its own `NOTICE` | A runtime dependency of `plugins/http-resolver` only. Nothing under `libs/` links it |

The full license text and the scope of each obligation are in `NOTICE`. The curl
license places no constraint on redistribution of a plugin binary. A binary
distribution of libcurl may carry further notices for the TLS backend it was
built against; on Windows and macOS this project expects the platform's own TLS,
which adds none. A packaged release records what its own build actually linked —
this one publishes no binary, so there is nothing further to record.

The decision and its grounds are
[ADR-0003](../adr/0003-http-client-dependency.md); the criteria are §13 of the
[design policy](../design/DESIGN_POLICY.md).

## 8. Known limitations

- **No cache.** Every read is a request, deliberately, so that the request
  pattern is visible before it is optimized. Sixteen adjacent 4 KiB index reads
  are sixteen requests, and eight readers doing identical work do it eight times
  over. Both numbers are in §4, and both are what `v0.3.0` exists to move.
- **No fallback when a server refuses `HEAD`**, per §2.
- **`If-Range` with a `Last-Modified` validator is implemented and not covered by
  the corpus.** The fixture server compares `If-Range` only against its `ETag`,
  so an asset with a date and no entity tag cannot exercise the conditional path
  there. The behavior is unit-tested against a scripted transport; the
  server-side half is what is missing.
- **A `206` covering less than was asked for is refused**, which is stricter than
  RFC 9110 requires. §10 of the design policy, DIAGNOSTICS.md §6, and the
  corpus's `ContentRangeTooShort` row all say to refuse it. The cost: an origin
  that caps the size of a range response is refused rather than read in pieces,
  and nothing in the corpus behaves that way. Relaxing it is a change to those
  documents first, for every backend.
- **The scheme-downgrade case is not in the corpus and cannot be.** The fixture
  server speaks plaintext HTTP, so there is no `https` to downgrade from. It is
  tested in `usdAssetHttp`'s own tests against a scripted `Location`.
- **The sanitizer lanes do not instrument libcurl.** It is the runner's own
  package, so the evidence is about this repository's code and not about the
  client behind the seam. That is the intended scope.
- **`ost plugin test` L2 cannot be satisfied by a network resolver**, so the two
  bundle cells are capped at `up_to: 1`. L2 asserts that `Resolve` returned a
  path, which for this resolver requires an origin to be listening; L3, L4, and
  L5 pass and are not in a cell.
  [Report 02](../reports/ost/02-2026-08-18-resolver-bundle-under-the-pyramid.md).
- **The Windows plugin lane is hand-authored.** `ost build` takes no prefix, no
  toolchain file, and no `-D`, and a generated cell renders a host-package
  installer for `apt` and `brew` only — so there is nowhere to put the vcpkg
  prefix libcurl needs.
  [Report 03](../reports/ost/03-2026-08-18-a-support-matrix-with-one-hand-authored-lane.md).
- **`ost library build` cannot resolve a library-to-library edge on its own**,
  carried forward from `v0.1.0`. It blocks nothing: the path this release is
  defined by is plain CMake and `ost build` over the workspace.
- **A generated cell cannot be given a step timeout**, so every generated cell
  inherits GitHub's six-hour job default. The hand-authored lanes bound their apt
  steps in minutes; the generated ones cannot. A stalled cell fails eventually,
  expensively.
- **The MSVC AddressSanitizer lane is unverified**, carried forward. A sanitizer
  is a property of the compiler, and MSVC implements only `address`.
- **The local validator is declared strong**, carried forward, with the caveat in
  the [module README](../../libs/usd-asset-local/README.md).

Open ADRs that constrain behavior:

| ADR | Status | Constraint |
| --- | --- | --- |
| [0001](../adr/0001-consumer-interface.md) | Accepted | The consumer interface is `ArAsset`. No consumer links this repository, in any release. The first integration is `v0.5.0` |
| [0002](../adr/0002-range-unsupported-policy.md) | Accepted | Range-unsupported is a hard error, with no whole-asset fallback. **Binding for the first time in this release**: both `NoAcceptRanges` and `IgnoresRange` are terminal, at open and at the first read respectively, and the whole body arriving is not permission to use it. `HTTP102` stays unallocated because of it |
| [0003](../adr/0003-http-client-dependency.md) | Accepted | libcurl, behind an internal transport seam, linked privately and statically, and absent from every installed header |

## 9. Migration notes

None required. `v0.1.0` consumers are unaffected: no `StatusCode` was removed or
redefined, no configuration name changed, and no default changed. Everything this
release adds is additive.

What is new to be aware of:

- **Diagnostic codes.** The `HTTPxxx` codes in
  [DIAGNOSTICS.md](../architecture/DIAGNOSTICS.md) are emitted for the first
  time. Adding a code is a minor change and changing what one means is a breaking
  one, and this release only adds. `HTTP102` remains unallocated by ADR-0002.
- **Configuration.** Five environment variables enter the surface
  ([CONFIGURATION.md](../reference/CONFIGURATION.md) §2). A bad value warns and
  takes that variable's default without discarding the other four.
- **Registration.** Installing the bundle registers `http` and `https` as URI
  schemes. It does not replace the primary resolver, and a local asset resolves
  exactly as it did — asserted by the bundle's own smoke fixture, which exists
  for that reason and looks like it tests nothing.
- **Range support is required.** An origin that does not serve ranges is an error
  rather than a slow success. If you were relying on whole-asset retrieval,
  ADR-0002 is the document that says no.

## 10. Reproducing this release

```text
git checkout v0.2.0

# Core only -- no OpenUSD installation required, no bundle
cmake --preset core && cmake --build --preset core && ctest --preset core

# Windows, from a plain shell
cmake --preset core-msvc && cmake --build --preset core-msvc && ctest --preset core-msvc

# Everything, including the ArResolver bundle. libcurl and OpenUSD, semicolon-separated
cmake --preset plugin-msvc -DCMAKE_PREFIX_PATH="<openusd>;<libcurl>"
cmake --build --preset plugin-msvc
ctest --test-dir build/plugin -C Release

# Sanitizers, GCC or clang only
cmake --preset core-asan && cmake --build --preset core-asan && ctest --preset core-asan
cmake --preset core-tsan && cmake --build --preset core-tsan && ctest --preset core-tsan
```

Eighteen tests in the core configurations and twenty-two with the bundle. The
four extra are the bundle's own: `httpResolver_configuration`,
`httpResolver_diagnostics`, `httpResolver_identifier`, and `httpResolver_stage` —
the last of which opens a `UsdStage` over a real socket, follows a relative
reference to a second remote layer, and asserts the `Range` header from the
fixture server's request log.

The recorded baseline is reproducible on its own:

```text
./build/core/tests/baseline/usdAssetHttp_baseline --output baseline.md
```

Byte counts are the same on every platform and in every configuration; the times
are not.
