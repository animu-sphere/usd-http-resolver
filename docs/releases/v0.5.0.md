# `v0.5.0` - Composable resolver product

- Date: 2026-08-27
- Tag: `v0.5.0`
- OpenUSD: 26.08
- OpenStrata producer: 0.22.8

## Scope

This release packages the existing HTTP resolver, asset reader, and persistent
cache implementation as an independently consumable runtime-composition
component. It adds artifact-owned acceptance tooling; it does not change the
v0.4.0 transport, validator, cache, or public C++ behavior.

The aggregate product contains `http-resolver` and installs
`share/usd-http-resolver/probes/packaged_probe.py`. The probe loads the resolver
through OpenUSD, opens a remote root layer and its relative child layer, and
requires a successful byte-range request. Producer build directories are not
used by the probe.

## Compatibility and baseline

- OpenUSD 26.08, CY2026 `usd` profile, Python 3.13.
- The source CI matrix is generated with OpenStrata 0.22.8 release pins.
- All v0.4.0 HTTP, validator, cache, diagnostics, and configuration contracts
  remain compatible.
- The I/O scenarios and expected request/byte behavior remain the v0.4.0
  baseline in `docs/reference/BASELINE.md`; this packaging-only release does
  not change the reader or cache algorithms.

## Release gates

The release preparation runs the shared boundary suite, hostile-server corpus,
sanitizer lanes, workspace tests, packaged HTTP acceptance, credential-output grep, release metadata
checker, product verification, and two identical package operations. The latter
must yield the same SHA-256 inventory for unchanged inputs. Platform artifact
digests are attached to the generated release evidence rather than copied into
this source record.

## Dependencies and licensing

No dependency or license changes. Apache-2.0 project files, `NOTICE`, and the
existing libcurl/OpenUSD attribution are retained in the source and product
evidence.

## Known limitations

- The packaged probe uses a loopback origin and a small USD layer; it proves
  resolver registration and range transport, not internet reliability or a
  large-file performance baseline.
- Binary products remain platform-specific. A composed runtime must select the
  product matching its exact OpenUSD target and ABI.
