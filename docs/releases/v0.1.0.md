## 1. What shipped

The release that decides whether the rest of the project is buildable. Its
centre of gravity is the test suite rather than the reader: the local file
backend is not interesting, and the harness that admits every later transport
is.

| Module | What it is |
| --- | --- |
| `libs/usd-asset-io` | The transport-independent core: the `AssetReader` random-access contract, `AssetMetadata`, the validator value types and their `Stable` / `Unstable` / `Unavailable` classification, the typed `StatusCode` vocabulary, the shared offset arithmetic in `ResolveReadRange`, and the metrics counters, latency histograms, and process aggregate |
| `libs/usd-asset-local` | The local-file backend and the correctness oracle: positional reads with no lock, size and range-support discovery at open, a filesystem-derived validator, and `AssetChanged` when an asset is republished underneath an open reader |
| `tests/boundary` | The shared boundary suite: the required boundary cases per fixture size, the short read below EOF, the mid-read revision change, biased property cases with shrinking and a reported seed, and the concurrency cases — all against an independent naive oracle that shares no code with the backend it checks |

Supporting infrastructure: the libs-first, OpenUSD-optional root build graph;
the `core`, `core-msvc`, `core-asan`, and `core-tsan` presets;
`.github/workflows/core-ci.yml` with the runtime-free core lane on three
platforms and the sanitizer lanes on Linux; `VERSION`, `LICENSE`, `NOTICE`; and
OpenStrata plain-library descriptors for both `libs/` modules.

Entering a backend is a row. The local backend's is
`tests/boundary/backends/boundary_local_main.cpp`, and that file is what
`v0.2.0` copies for HTTP.

## 2. What explicitly did not ship

No network code, in any form. No `ArResolver` registration, no plugin bundle, no
OpenUSD link from anything in `libs/`. No cache of any kind, and no async. The
cache counters are defined and stay at zero.

`openstrata.ci.yaml` does not exist. No `ost` cell shape can name this
workspace at `v0.1.0`: every `SupportCell` pins and materializes an OpenUSD
runtime, which would remove the property the core lane exists to demonstrate,
and `verify: graph` — the one runtime-free rung — fails with
`PRECONDITION_FAILED: no plugin bundles found in the workspace member set`. The
lanes are hand-authored for that reason, and the two runtime-free ones stay
outside the matrix after it arrives in `v0.2.0`. Full account and the two
upstream asks:
[report 01](../reports/ost/01-2026-08-16-v0.1.0-ci-without-a-support-matrix.md).

## 3. Capability delta

There is no previous release, so the delta is the whole of
[the capability matrix](../reference/CAPABILITY_MATRIX.md) marked *implemented*
as of this tag: local file random access; validator value types, local
validator capture, local revision binding, and local `AssetChanged`; the typed
status vocabulary and credential elision; per-asset counters, latency
distributions, and the `USD_HTTP_RESOLVER_METRICS_DUMP` dump; the boundary
suite with its property and concurrency rows; the sanitizer builds; and the
OpenUSD-free core lane in CI.

Everything else in that document is *planned*, *deferred*, or *not planned*.

## 4. Recorded baseline

**None, and none was due.** The baseline requirement in
[METRICS.md](../architecture/METRICS.md) §6 binds a release that changes I/O
behavior. Four of its five scenarios — metadata-only open, header-and-index
read, bounded spatial query, and parallel readers — measure a transport and a
cache, and this release has neither; the fifth, the full sequential read,
compares a range-based reader against a plain download and has no meaning when
the reader is `pread` on a local file. The first recorded baseline is `v0.2.0`'s,
and it is the first release whose byte counts can regress.

What is evidenced here instead is that the counters are populated and can carry
a baseline when there is one. Over the boundary suite's fixed row on Windows,
against the seven fixtures in
`%TEMP%\usd-http-resolver-boundary-local-fixed\`:

```text
assetSize            589831
bytesRequested       4349258
bytesTransferred     1414799
bytesFromCache       0
requestCount         211
metadataRequestCount 109
retryCount           0
redirectCount        0
openLatency us       p50 4095 p90 5866 p99 5866 max 5866
requestLatency us    p50 3    p90 3    p99 15   max 22
readLatency  us      p50 3    p90 7    p99 31   max 33
```

That is a suite aggregate over many readers and many fixtures, not a scenario
measurement. It is recorded as proof that the counters move, and it is not a
comparison point for any later release. `bytesFromCache` is zero because no
cache exists, not because none hit.

## 7. Third-party dependencies and licenses

None. Both libraries depend on the C++17 standard library, `Threads`, and
platform system calls. Nothing is vendored and nothing is fetched at configure
time. The project is Apache-2.0; see `LICENSE` and `NOTICE`.

The HTTP client dependency is chosen in `v0.2.0` on license, footprint, and
Wasm viability, and recorded as an ADR. Its obligations enter `NOTICE` then.

## 8. Known limitations

- **The MSVC AddressSanitizer lane is unverified**, and the build says so. A
  sanitizer is a property of the compiler; MSVC implements only `address`, and
  the sanitizer evidence for this project is a GCC or clang lane. The CI cells
  are Linux for that reason.
- **No I/O baseline exists**, per §4. The project's central claim is a byte
  ratio, and nothing here measures one yet.
- **`openstrata.ci.yaml` does not exist**, per §2.
- **`ost library build` cannot resolve a library-to-library edge on its own.**
  `libs/usd-asset-local` declares `requires.libraries: [usdAssetIo]` and builds
  through plain CMake, through `ost library build libs/usd-asset-io`, and
  through the root tree; `ost library build libs/usd-asset-local` fails to find
  the `usdAssetIo` package, because nothing installed it into a shared prefix
  first. Reproducible in `usd-vrm-plugins`, so it is a workflow question rather
  than a defect in these descriptors. It blocked nothing here — the path this
  release is defined by is plain CMake — and it is worth resolving before the
  `v0.2.0` bundle consumes the closure.
- **The local validator is declared strong**, with the caveat recorded in the
  [module README](../../libs/usd-asset-local/README.md). It is derived from
  device, file id, size, and mtime, and inherits the resolution of the
  underlying filesystem's timestamps.

Open ADRs that constrain behavior:

| ADR | Status | Constraint |
| --- | --- | --- |
| [0001](../adr/0001-consumer-interface.md) | Accepted | The consumer interface is `ArAsset`. No consumer links this repository, in any release |
| [0002](../adr/0002-range-unsupported-policy.md) | Accepted | Range-unsupported is a hard error from `v0.2.0`, with no whole-asset fallback. Nothing in this release can encounter it |

## 9. Migration notes

None. There is no previous release to migrate from. Every diagnostic code,

## 10. Reproducing this release

```text
git checkout v0.1.0

# Windows, from a plain shell
cmake --preset core-msvc && cmake --build --preset core-msvc && ctest --preset core-msvc

# Linux or macOS
cmake --preset core && cmake --build --preset core && ctest --preset core

# Sanitizers, GCC or clang only
cmake --preset core-asan && cmake --build --preset core-asan && ctest --preset core-asan
cmake --preset core-tsan && cmake --build --preset core-tsan && ctest --preset core-tsan
```

Nine tests in each: four in `usdAssetIo`, two in `usdAssetLocal`, and the
boundary suite's `fixed`, `property`, and `concurrent` rows against the local
backend. No OpenUSD installation is required, or used, by any of them.
